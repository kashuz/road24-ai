# FastAPI conventions

Async clean architecture: **Router → Service → Repository**. (Install this rule in FastAPI repos; for
road24-backend use `backend-django` instead — both are `.py`.)

## Architecture
- Routers are thin: validate (Pydantic v2), build deps (constructor DI), call one service — no logic/IO.
- Services hold business logic, expose `execute()`, are idempotent for payment/insurance flows.
- Repositories are the only layer touching DB/HTTP; return DTOs/domain objects, not raw ORM rows — keeps
  layers testable and swappable.
- Everything `async`; no blocking I/O in async paths.

## Style
- Full Py 3.12 type hints, `StrEnum` not magic strings, guard clauses, short functions, `logger` not `print`.
- Pydantic v2 schemas at the boundary with camelCase aliases; reuse the shared paginated/envelope wrappers.

## Security
- Auth dependency on protected routes; authorize the specific object (no IDOR). Validate all input.
- Parameterized queries only; allow-list outbound URLs in httpx (SSRF). Never log secrets/PII (SDK sanitizes).

## Data & messaging
- Schema changes via Alembic — review the autogenerated SQL; plan expand→migrate→contract for zero downtime.
- RabbitMQ consumers/publishers (insurance) thin → service; idempotent; publish after commit.

## Tests
- `pytest` with markers (`unit`/`repository`/`service`/`router`/`schema`); fake repos for services,
  mocked httpx for HTTP repos; cover failure paths. `ruff` + `mypy` clean before "done".

# Create a Django Model (road24-backend)

Model for: $ARGUMENTS

Models live in `apps/<app>/models/`. Inherit from `BaseModel` (soft delete + timestamps) — see
`apps/shared`. Then generate + review the migration.

## Steps

1. **Read first** — `apps/shared` `BaseModel`, a sibling model in the target app, and existing
   migrations. Match field/index/Meta conventions.
2. Define the model; add indexes for filtered/foreign-key columns; choose `on_delete` deliberately.
3. Generate + **review** the migration; apply it.
   ```bash
   python manage.py makemigrations <app>
   # read the generated migration, then:
   make migrate
   ```

## Template

```python
from django.db import models

from apps.shared.models import BaseModel


class Hold(BaseModel):
    class Status(models.TextChoices):
        PENDING = "pending", "Pending"
        CONFIRMED = "confirmed", "Confirmed"

    vehicle = models.ForeignKey("cars.Car", on_delete=models.PROTECT, related_name="holds")
    amount = models.PositiveBigIntegerField()
    status = models.CharField(max_length=16, choices=Status.choices, default=Status.PENDING)

    class Meta:
        db_table = "holds"
        indexes = [models.Index(fields=["vehicle", "status"])]
```

## Rules

- Inherit `BaseModel` — soft deletes only; never hard-delete domain rows. Don't override the manager
  in a way that exposes soft-deleted rows by default.
- `TextChoices`/`IntegerChoices` instead of magic strings. Index FKs and common filter columns.
- Pick `on_delete` consciously (`PROTECT` for financial/reference data). Money as integer (minor units).
- Review the autogenerated migration (data loss, defaults, nullable→not-null). Keep migrations small.
- Keep query/business logic out of the model — that's services + repositories.
